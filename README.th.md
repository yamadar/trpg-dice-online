## ทำไมเลือกตัวนี้สำหรับเซสชันถัดไป

- **แชร์รหัส แล้วเริ่มทอยได้เลย** GM สร้างห้องและอ่านรหัส 4–6 ตัวอักษรให้ฟัง ที่เหลือก็แค่พิมพ์ตาม ไม่มีบัญชี ไม่มีอีเมลยืนยัน ไม่มีอะไรต้องลงทะเบียน
- **ผลทอยอยู่กันแค่ในวง** P2P เต็มรูปแบบบน WebRTC — ผลทอยและแชตเดินทางจากเครื่องหนึ่งสู่อีกเครื่องโดยตรง ไม่ผ่านเซิร์ฟเวอร์ใดของเราเลย
- **เหมาะกับมือถือบนโต๊ะ** เลย์เอาต์ออกแบบเพื่อมือถือมาก่อน ติดตั้งเป็น PWA บน iOS และ Android ได้ เปิดแบบเต็มจอ
- **รองรับ 19 ภาษา และแปลแชตอัตโนมัติ** นักบวชเยอรมันสามารถหยอกกับโจรญี่ปุ่นได้โดยไม่มีใครหลุดบรรยากาศ
- **ออกแบบให้อยากเปิดอีก** ตัวละคร แพตเทิร์น ธีม ขนาดตัวอักษร และเซสชันที่ผ่านมา ทั้งหมดเก็บไว้ในเครื่อง แอปจึงรู้สึกเหมือน*กล่องลูกเต๋าของคุณเอง* ไม่ใช่ตู้บริการสาธารณะ

## เริ่มเซสชันใน 30 วินาที

1. **GM:** เปิดเดโม แตะ **ห้อง → สร้าง** แล้วอ่านรหัสให้ฟัง
2. **ผู้เล่น:** เปิดเดโม แตะ **ห้อง → เข้าร่วม** แล้วพิมพ์รหัส
3. **ทุกคน:** ทอย แชต และเฮกับเลขสิบ-ทเวนตี้เนเชอรัลแรกพร้อมกัน

GM เป็นโฮสต์ ตราบใดที่แท็บของเขายังเปิดอยู่ ห้องก็ยังมีชีวิต ปิดแท็บคือจบเซสชัน — ห้องที่ผ่านมายังถูกเก็บไว้ในเครื่อง สามารถกลับมาอ่าน log ภายหลังได้

## ในกล่องลูกเต๋ามีอะไรบ้าง

### ลูกเต๋าที่อ่านผลได้ในพริบตา

`d4 · d6 · d8 · d10 · d12 · d20 · d100` พร้อมจำนวน ค่าบวกลบโมดิฟายเออร์ และประเภท **ดาเมจ / ตัดสิน** ที่จัดวลีผลทอยให้เหมือนที่โต๊ะพูดจริง — *"ผลของการตัดสินสังเกตการณ์: 18"*, *"ดาบใหญ่: ดาเมจ 11"* แต่ละหน้าของลูกเต๋าจะแสดงเป็นไอคอนเงาขนาดเล็กที่ตรงกับรูปร่างลูกเต๋านั้น ทำให้อ่านง่ายในพริบตา

### แพตเทิร์น — ท่าเด็ดของคุณ พร้อมใช้แค่แตะเดียว

บันทึก `2D6 + 3 — ดาเมจ` ด้วยชื่ออย่าง *"ดาบใหญ่"* แล้วเรียกใช้ในเทิร์นถัดไปด้วยการแตะเดียว แพตเทิร์นเป็นของตัวละครเป็นหน้า ๆ ดังนั้น PC สองตัวบนเครื่องเดียวกันจะมีคลังของตัวเองแยกกัน

### ตัวละครพร้อมภาพประจำตัว ข้อความบันทึก และแพตเทิร์นเฉพาะตัว

ผู้เล่นหนึ่งคนมี PC ได้หลายตัว แต่ละตัวมีชื่อ ภูมิหลังที่แชร์ในห้อง บันทึกส่วนตัวที่เห็นแค่คุณ ภาพประจำตัว (ใส่หรือไม่ใส่ก็ได้) คลังแพตเทิร์น และค่าพรีเฟอเรนซ์ *"รวมบันทึกตอนเอ็กซ์พอร์ตด้วยไหม"* รายตัวละคร เอ็กซ์พอร์ตเป็น JSON เพื่อสำรอง อิมพอร์ตเข้าอีกเครื่องเพื่อพา PC ไปเซสชันถัดไป เมื่อสวมบทบาทเป็นตัวละคร ชื่อจะแสดงเป็น `ตัวละคร (ผู้เล่น)`

### ฟีดเดียวสำหรับทั้งทอยและแชต

ผลทอยและแชตอยู่ในไทม์ไลน์เดียวกัน พร้อมตัวกรอง **ทั้งหมด / ทอย / แชต / ไฟล์** การพิมพ์ `@` มีตัวเติมข้อความอัตโนมัติให้ระบุผู้เล่นถูกต้อง `@all` ส่งถึงทุกคน แนบรูปลงแชตได้ ระบบจะลดขนาดให้อัตโนมัติก่อนส่ง

### กลับไปอ่านห้องเก่าได้

ทุกเซสชันที่ผ่านมาถูกเก็บไว้ในเครื่องเป็น log ถาวร เปิดห้องเก่าแบบอ่านอย่างเดียวได้จากล็อบบี้ แตะชื่อผู้เล่นในฟีดเก่าเพื่อดูสแนปช็อตของตัวละครและภาพประจำตัวล่าสุดที่จดเอาไว้ เอ็กซ์พอร์ตทั้งห้อง (แชต ทอย รูปภาพ) เป็น ZIP ก้อนเดียวก็ได้

### เครื่องมือสำหรับ GM

GM ทอย **แบบลับ** ได้ คนอื่นจะเห็นแค่ *"มีการทอยแบบลับเกิดขึ้น"* แต่ไม่เห็นตัวเลข ส่วน GM ยังรวบการเปลี่ยนชื่อห้องและสร้างรหัสใหม่ไว้ใต้ disclosure และปุ่มออกของ GM เขียนว่า **ปิดห้อง** เพื่อให้ชัดเจนว่าจบเซสชันให้ทุกคน

### UI 19 ภาษา &amp; แปลแชตอัตโนมัติ

UI รองรับ 19 ภาษา การแปลแชตอัตโนมัติ (เลือกได้) จะใช้ Chrome Translator API บนเครื่องก่อนหากมี ถ้าไม่มีก็จะตกไปใช้ REST API ของ [MyMemory](https://mymemory.translated.net/) ที่ไม่ต้องใช้คีย์ แตะ **ต้นฉบับ** บนข้อความที่ถูกแปลเพื่อดูข้อความเดิมตามที่ส่งมา

### ของเล็ก ๆ ที่ทำให้ใช้สบาย

สีประจำของผู้เล่นที่ไม่เปลี่ยน อินดิเคเตอร์เบา ๆ ตอนพิมพ์ เหตุการณ์เข้า / ออกห้องโชว์ในฟีด เปลี่ยนธีมได้ ปรับขนาดตัวอักษรได้ และพฤติกรรมที่อ่อนโยนตอน GM ปิดห้อง

## ติดตั้งบนมือถือ (PWA)

เว็บเป็น Progressive Web App สามารถเพิ่มลงโฮมสกรีน iOS และ Android แล้วเปิดแบบเต็มจอ — ไม่มี UI เบราว์เซอร์ เปิดซ้ำเกือบจะทันที

- **Android (Chrome):** เปิดเดโม แตะเมนูเบราว์เซอร์ เลือก **ติดตั้งแอป** (หรือ *เพิ่มในหน้าจอหลัก*)
- **iOS (Safari):** เปิดเดโม แตะปุ่มแชร์ เลือก **เพิ่มที่หน้าจอโฮม**

Service worker พรีแคชเชลล์ของแอปเพื่อเปิดทันทีเมื่อกลับมา แต่ตัวห้องจริง ๆ ยังคงเป็น P2P ผ่าน WebRTC และต้องมีเครือข่ายอยู่

**แนวจอ:** manifest ไม่ล็อกหรือทับการหมุน PWA ที่ติดตั้งจะอิงค่าหมุนอัตโนมัติ / ล็อกหมุน ของเครื่อง (เช่นใน Android หากปิดหมุนอัตโนมัติ เอียงเครื่องไปก็จะคงแนวเดิม)

## โหมดออนไลน์ทำงานอย่างไร

ห้องใช้ **WebRTC peer-to-peer** ผ่าน [PeerJS](https://peerjs.com/) ผู้สร้างห้อง (GM) เป็นโฮสต์ ผู้เล่นคนอื่นเชื่อมตรงไปยัง GM และ GM เป็นตัวส่งต่อสถานะที่แชร์ ไม่มีข้อมูลเกมใดผ่านเซิร์ฟเวอร์ของโปรเจ็กต์นี้ เนื่องจากเป็น P2P ห้องจะเปิดอยู่เฉพาะตราบที่ GM เปิดแท็บไว้

## เทคโนโลยีที่ใช้

- [Vite](https://vite.dev/) + [React 19](https://react.dev/) + TypeScript

## ตั้งค่า (TURN relay, ตัวเลือกเสริม)

WebRTC ต้องใช้ TURN relay เพื่อต่อให้ผู้เล่นที่เครือข่ายบล็อก UDP หรือใช้ NAT แบบสมมาตร (พบบ่อยใน Wi-Fi คาเฟ่ / สาธารณะ) ค่าเริ่มต้นจะตกไปใช้ TURN server ฟรีของ Open Relay Project — เหมาะกับการใช้สบาย ๆ แต่เป็น best-effort

หากต้องการ relay ที่เชื่อถือได้ ก็อปปี้ `.env.example` ไปเป็น `.env` แล้วตั้งค่า:

- `VITE_TURN_URLS` — URL TURN คั่นด้วยจุลภาค ใส่รายการ `turns:` บน TCP/443 เพื่อให้ทำงานในกรณีที่ UDP ถูกบล็อก
- `VITE_TURN_USERNAME` — ชื่อผู้ใช้ TURN
- `VITE_TURN_CREDENTIAL` — credential / รหัสผ่าน TURN

> **หมายเหตุความปลอดภัย:** Vite จะ inline ตัวแปร `VITE_*` ทุกตัวเข้าบันเดิล production ทำให้ credential TURN ที่ตั้งไว้ที่นี่เห็นได้สำหรับใครก็ตามที่เปิดหน้า ใช้ credential TURN แบบมีอายุสั้น / ชั่วคราว (เช่นแพตเทิร์น time-limited credential ของ TURN REST API) และเปิดข้อจำกัดฝั่งผู้ให้บริการ — origin ที่อนุญาต, IP filtering, โควต้ารายเดือน อย่านำ credential production ที่อายุยาวมาใช้ที่นี่ซ้ำ

หากต้องการใช้ใน GitHub Pages ให้เพิ่มเป็น secrets ของรีโพ และส่งต่อในขั้นบิลด์ใน `.github/workflows/deploy.yml` ตัวเลือกฟรี เช่น แพ็กเกจฟรีของ [Metered](https://www.metered.ca/) หรือ self-host [coturn](https://github.com/coturn/coturn)

## การเดปลอย

push ไป `main` จะ trigger workflow GitHub Actions (`.github/workflows/deploy.yml`) ซึ่งจะรัน lint, test, build แล้วเผยแพร่ขึ้น GitHub Pages base path ของ production คือ `/trpg-dice-online/`; ทับด้วยตัวแปรสภาพแวดล้อม `BASE_PATH` ได้ถ้าจะโฮสต์ที่อื่น
