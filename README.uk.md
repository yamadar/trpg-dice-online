Онлайн-кидач кубиків для настільних ігор: кидайте кубики, зберігайте
шаблони для повторного використання, обмінюйтеся результатами, історією
та чатом з компанією в реальному часі — все це зі статичної сторінки без
бекенду.

**🎲 Демо:** https://yamadar.github.io/trpg-dice-online/

## Можливості

- **Кубики (A)** — обирайте кількість і тип перед кожним кидком
  (`D4, D6, D8, D10, D12, D20, D100`). `D100` кидає два d10 як цифри;
  `00` читається як 100.
- **Модифікатор (B)** — додавання/віднімання цілого до результату.
- **Тип (C)** — `шкода` або `перевірка`.
- **Персонажі** — ведіть кількох персонажів (ім’я, публічна передісторія,
  особиста нотатка, опціональний портрет, список шаблонів та налаштування
  «додавати нотатку в експорт» окремо для кожного), перемикайтеся та
  експортуйте/імпортуйте як JSON.
- **Шаблони** — поєднуйте A + B + C з назвою та зберігайте для кожного
  персонажа; кидайте збережене одним дотиком зі списку.
- **Стрічка історії та чату** — кидки і чат в одній хронологічній стрічці
  з фільтром Все / Кидки / Чат / Файли.
- **Історія минулих кімнат** — кожна сесія зберігається; переглядайте
  стрічку лише для читання з лобі та видаляйте посесійно або все одразу.
  Дотик до імені показує знімок персонажа і останній відомий портрет.
- **Онлайн-кімнати** — окремі екрани «Створити» / «Приєднатися» з кодом
  кімнати (мінімум 4 символи; автоматичні — 6). Історія, чат і список
  гравців синхронізуються P2P; після перезавантаження ведучий перехостить,
  гравець перепідключиться автоматично.
- **Налаштування ведучого** — зміна назви та коду кімнати в згорнутому
  розділі ведучого, а кнопка виходу — «Закрити кімнату».
- **Приховані кидки ведучого** — ведучий може приховати значення; інші
  бачать лише, що відбувся прихований кидок.
- **Кольори гравців та індикатор набору** — кожному учаснику призначений
  стабільний колір, а м’який індикатор показує, хто набирає.
- **Події кімнати** — входи/виходи з’являються в стрічці; закриття
  кімнати ведучим коректно повідомляє всіх.
- **Багатомовність і авто-переклад** — інтерфейс підтримує 19 мов.
  Необов’язковий авто-переклад показує повідомлення інших гравців мовою
  вашого інтерфейсу; перевагу надає вбудованому Chrome Translator API, у
  разі недоступності використовує безключовий REST API
  [MyMemory](https://mymemory.translated.net/). Натисніть «Оригінал» біля
  перекладеного повідомлення, щоб побачити вихідний текст.

## Як працює обмін онлайн

Застосунок використовує **WebRTC P2P через [PeerJS](https://peerjs.com/)**.
Творець кімнати (ведучий) виконує роль хоста; інші підключаються
безпосередньо до ведучого, який ретранслює спільний стан. Жодні дані не
проходять через сервери проєкту. Через P2P кімната існує лише поки
сторінка ведучого відкрита.

## Конфігурація (TURN-релей)

WebRTC потребує TURN-релею, щоб з’єднувати гравців, чия мережа блокує
UDP або використовує симетричний NAT (часто у публічних Wi-Fi). Типово
застосунок використовує безкоштовні публічні TURN-сервери Open Relay
Project — підходить для випадкового вжитку, але «best effort». Для
надійного релею скопіюйте `.env.example` у `.env` і задайте:

- `VITE_TURN_URLS` — TURN-URL через кому. Додайте запис `turns:` через
  TCP/443, щоб працювало й там, де блокують UDP.
- `VITE_TURN_USERNAME` — ім’я користувача TURN.
- `VITE_TURN_CREDENTIAL` — дані TURN (пароль).

**Зауваження щодо безпеки:** Vite вбудовує всі змінні `VITE_*` у
production-бандл, тож облікові дані TURN, задані тут, будуть видимі
будь-кому, хто відкриє сторінку. Щоб зменшити ризик зловживань,
використовуйте короткоживучі / тимчасові облікові дані TURN (наприклад
патерн часово обмежених даних через TURN REST API) у поєднанні з
обмеженнями на стороні провайдера — дозволені origin, фільтри IP, місячні
квоти. Не використовуйте тут довгоживучі production-облікові дані
повторно.

Щоб використовувати у деплої GitHub Pages, додайте їх як секрети
репозиторію та передайте на кроці build у `.github/workflows/deploy.yml`.
Безкоштовні варіанти: безкоштовний тариф [Metered](https://www.metered.ca/)
або самостійний хостинг [coturn](https://github.com/coturn/coturn).

## Розгортання

Push до `main` запускає робочий процес GitHub Actions
(`.github/workflows/deploy.yml`): лінт, тести, збірка і публікація на
GitHub Pages. Базовий шлях у проді — `/trpg-dice-online/`; перевизначається
змінною середовища `BASE_PATH` для іншого хостингу.
