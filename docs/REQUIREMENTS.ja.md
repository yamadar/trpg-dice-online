# Dice & Chat — 要件定義 / 実装プラン

[English](REQUIREMENTS.md)

> オンライン TRPG セッションを簡単に。要件定義と実装プラン。

## 1. 概要

オンラインで各種ダイスを振り、結果を他のプレイヤーとリアルタイムで共有できる SPA。

- 静的サイトとして GitHub Pages にホストする
- バックエンドサーバーを持たず、ブラウザ間 P2P (PeerJS) で同期する
- 19 言語の UI 切り替えと、チャットの自動翻訳に対応

## 2. 用語

| 用語 | 定義 |
|------|------|
| ダイス (A) | 振るサイコロの「個数」と「種類」 |
| 補正 (B) | 出た値に加減する整数 |
| 種類 (C) | パターンの用途。`ダメージ` / `判定` の二種 |
| パターン | A + B + C の組み合わせ |
| 出目 | ダイスの合計 + 補正 |
| ロール | パターンを実際に振った一回の行為と結果 |
| ルーム | プレイヤーが集まる共有セッション |
| GM | ルームを作成したゲームマスター。ホストを兼ねる |
| テーブルマップ | ルームのマップ画面。背景画像・グリッド・トークンで構成される共有空間 |
| トークン | テーブルマップ上に置く駒。PC トークン（キャラに紐付く）と GM 専用トークン（NPC・モンスター用）の 2 種 |
| グリッド | テーブルマップに敷くマス目。現在はスクエアに対応 |

## 3. 機能要件

### 3.1 ダイス (A)
- 振る前に毎回「個数」と「種類」を指定できる
- 種類: `D4, D6, D8, D10, D12, D20, D100`
- `D100` は D10 を 2 個振り、片方を 10 の位、もう片方を 1 の位として算出する。
  両方が 0 のときは 100 とする（範囲 1–100）。

### 3.2 補正 (B)
- 出目に対しプラス／マイナスの整数補正をかけられる。

### 3.3 種類 (C)
- `ダメージ` と `判定` の二種類。

### 3.4 パターン
- A + B + C を 1 つのパターンとして扱う。
- 名前を付けて保存できる。
- 同名・同用途のパターンが既に存在する場合は、置き換える（更新する）かを確認する。
- 保存したパターンは一覧から呼び出して再利用できる。
- 一覧からワンクリックで直接振れる（クイックロール）。
- 一覧内でパターンを並び替えできる。順序は書き出し／読み込みでも保たれる。
- パターンの削除は誤操作防止のため確認ダイアログを必須とする。
- パターンが無い場合は、そのキャラクターにパターンが無い旨と、パターンが
  キャラクター単位であることを明示する。
- 保存先はブラウザの localStorage（個人ごと）。

### 3.5 ロールと出目の表記
- 出目 = ダイス合計 + 補正。
- 種類が `ダメージ`: 「`{パターン名}` `{出目}`ダメージ」（名前なしは「`{出目}`ダメージ」）。
- 種類が `判定`: 「`{パターン名}` 判定の結果 `{出目}`」（名前なしは「判定の結果 `{出目}`」）。

### 3.6 履歴とチャットの統合表示
- すべてのロール結果を時系列の履歴として残す。
- 履歴にはダイスの内訳（各目）も保持する。フィードの出目内訳は各ダイスを
  真上から見た形（D4/D8/D20 は三角形・正方形 + X / 六角形、D6 は正方形、
  D10 は縦長の菱形、D12 は正五角形、D100 は円）の SVG アイコンに数字を
  載せて表示する。
- 履歴とチャットは 1 つのフィードに時系列で統合表示する。
- 各エントリの時刻は `H:mm` で表示する。フィードの先頭と日付を跨ぐ位置には、
  年月日（UI 言語に応じた表記）を中央に置いた区切り線を入れる。
- 「すべて / ダイス / チャット / ファイル」で表示を絞り込める。
  フィルタチップはアイコンのみ（多言語ラベルは `aria-label` と
  ツールチップで保持）で、UI 全体と統一感のあるアイコン体系を採用する。
  「すべて / チャット / ファイル」は Lucide、「ダイス」は Game Icons の
  6 面ダイス透視シルエット（CC BY 3.0、[CREDITS](CREDITS.ja.md) 参照）。
  同じ d6 を Dock の「ダイス」やチュートリアルのダイスステップでも
  使い、ダイスの表象を 1 つに統一する。
- 参加者ごとに固有の色を割り当て、フィードと参加者一覧で見分けやすくする。
- フィードはチャットアプリのバブル形式で表示する。自分の発言・ロールは
  右寄せ、他の参加者のものは左寄せに並べる。各エントリには円形アイコンを
  添え、キャラクターにポートレートが設定されていればその画像を、なければ
  参加者色のドットを表示する。
- フィードの発言・ロールが GM のものなら、名前の横に GM マークを表示する。
- 表示のクリアは誤操作で行われないよう、確認ダイアログを必須とする。
- 同じシステムメッセージ（「○○が参加しました」等）が連続したら 1 行にまとめ、
  末尾に「(n)」で件数を示す。
- 設定メニューでフィードをコンパクト表示に切り替えられる。コンパクト時は
  各エントリを 1 行（時刻・名前・内容）に詰め、アバター・プレイヤー色の
  ドット・名前の「（プレイヤー名）」を省いてキャラクター名のみを表示する
  （色付きの名前で発言者を識別する）。時刻は左の定位置に置き、長い発言は
  折り返して 2 行目以降を名前の位置に揃える。設定はブラウザに保存される。
- 設定で自動翻訳をオンにすると、チャットを設定言語へ翻訳して表示する。
  翻訳は端末内の Chrome Translator を優先し、使えない場合は MyMemory へ
  自動でフォールバックする。各メッセージは原文に戻せ、翻訳中は原文に
  アニメーションを添える。翻訳は表示層で完結し、両方式とも失敗した場合は
  原文を表示する。
- 表示は直近のみだが、上限を超えて遡る古い履歴は「これより前を読み込む」で
  永続ログからオンデマンドに読み込める。
- ルームの全履歴（参加者一覧、ダイス・チャット・添付ファイル、各発言時の
  プレイヤー／キャラクター情報、キャッシュ済みのチャット翻訳）を ZIP 書庫に
  エクスポートできる。書庫からルームの状態を復元できるだけの情報を含む。
- エクスポートした ZIP 書庫を読み込み、その内容でルームを復元できる
  （読み込んだ本人がホストとしてルームを再開する）。
- フィードの名前をタップすると、そのキャラクターの最新の名前・
  プレイヤー名・背景情報をカードで表示する（PC・モバイル両対応）。
  キャラクターの同一性は `characterId` で参照され、同じ characterId
  の過去発言は現在の名前・背景・ポートレートで表示される
  （`sessionCharacters` の per-character レコードを表示権威とする）。

### 3.7 オンライン共有
- ルームを作成・参加でき、ロール履歴・チャット・参加者一覧を共有する。
- ルーム作成者が GM 兼ホストになる。
- ルームの作成画面・参加画面の両方に、「GM はルームのホストになるため、
  GM がオフラインになると参加者も切断される」という P2P スター型の制約を
  示すヒントを表示する。ルームに入る前にこの依存関係を知らせる。
- ロビーは「ホーム → 作成 / 参加 / 過去のルーム」と画面を分割する。作成画面
  ではルーム名と任意コードを入力でき、参加画面はコード入力のみ。`?room=コード`
  付きで開いた場合は参加画面をプリフィルして表示する。
- 入室中の表示は、参加者一覧をアバター付きで上部に大きく出す。ルーム名と
  ルームコードの変更は GM 専用の `<details>` セクションに集約し、それぞれ
  「名前を変更」「コードを変更」ボタンで明示的に確定する。GM の退出ボタンは
  「ルームを閉じる」と表記する。
- ルーム作成時、GM はルームコードを指定できる（空欄なら自動生成）。指定した
  コードが他のルームで使用中の場合はエラーを表示する。
- GM は参加中のルームのコードを変更できる。参加者は自動的に新しいコードへ
  移行し、履歴は保持される。他のルームのコードには影響しない。
- GM はルームに名前を付けられ、ルーム名は参加者全員に共有される。
- ルーム内のやり取り（ロール・チャット・参加者）はそのルーム内で完結し、
  他のルームには一切影響しない。
- ルームごとに URL（`?room=コード`）を発行し、リンクの共有で参加できる。
- `?room=コード` 付きの URL で開いたとき（リロード時も含む）は、手動操作を
  待たず自動でそのルームへの参加を試みる。
- リロードからの復帰: そのタブが GM だったルームは、同じコードで自動的に
  再ホストし、会話（履歴・チャット）を永続ログから復元する。参加者だった
  場合は再参加する。タブ単位の判定なので、別タブや新規起動では復元しない。
- ルーム参加の試行中は「接続中」を表示する。
- 意図しない切断（タブのバックグラウンド化・通信断など）は自動で同じルームへ
  再接続を試みる。再接続の間隔は最長 5 秒に抑え、「退出」を押した意図的な
  切断では再接続しない。
- GM がオフラインになると、参加者には再接続中のバナーを表示する。再接続でき
  ないまま長時間が過ぎたら「GM が不在のためオフラインになりました」と通知して
  オフラインに戻す。
- GM がオフラインの間に参加者が送ったチャットは未送信として自分のフィードに
  表示され、再接続できたとき順番に送信される。
- ルーム未参加でもローカル単体で利用できる（オフラインモード）。

### 3.8 GM の隠しロール
- GM は「隠しロール」設定を ON にできる。
- ON のとき GM のロールは他プレイヤーに出目を伏せて通知される。
- 他プレイヤーには「GM が隠しロールを行いました」とだけ表示される。
- GM 自身は自分の出目を確認できる。
- 「隠しロール」はパターンの属性として保存される。隠しロール属性を持つ
  パターンでも、GM でないプレイヤーが使った場合はダイスは振れるが隠し
  ロールにはならない。隠しロール属性はパターン一覧で GM のときだけ表示
  され、GM でないときは表示されない。属性はキャラクターの書き出し／
  読み込みでも保持される。

### 3.9 チャット
- ルーム参加者でテキストチャットができる。
- 他の参加者が入力中のとき、控えめに「入力中…」を表示する。
- 「入力中…」表示は、受信側と送信側を別々に設定メニューから無効化できる。
  「他の人の入力中を見る」を OFF にすると相手のシグナルを受け取っても表示
  しない。「自分の入力中を他者に通知」を OFF にすると自分のキーストロークから
  シグナルを一切送らない。どちらも既定 ON、ブラウザに保存される。
- チャットにファイルを添付できる。バックエンドを持たないため、ファイルは
  base64 データ URL として P2P 経路で送信する。画像は送信前に縮小する。
- 画像の添付はフィードにサムネイルで表示し、タップで全画面ビューア
  （ライトボックス）を開く。画像以外はダウンロード用のチップで表示する。
- ライトボックスは左右スワイプ・矢印キー・画面の前後ボタンで、フィード内の
  他の画像へ移動できる。
- フィードのフィルターに「ファイル」を追加し、添付付きメッセージのみを
  一覧表示できるようにする。
- 「@ユーザー名」でそのユーザーを、「@all / @ALL」で全員をメンションでき、
  対象ユーザーにはそのメッセージが強調表示される。メンションはプレイヤー
  ID で保持し、名前変更や同名ユーザーがいても正しく扱う。入力中に「@」を
  打つとユーザー名のサジェストを表示する。

### 3.10 ルームの退出・終了
- GM の退出はルームの終了を意味する。GM には確認を求め、各クライアントには
  「GM がルームを閉じました」と通知する（接続エラー扱いにしない）。
- ルームの参加・退出はフィードにシステムメッセージとして記録する。
- 退出後も履歴は残すが、退出済みルームの記録だと分かるよう淡く表示する。
- 「退出」を押さずに切断した場合（タブを閉じる・通信断・リロード等）も、
  ハートビートで検知して参加者一覧から取り除く。同じプレイヤーが再参加した
  際は古い接続を破棄し、二重表示しない。

### 3.11 多言語
- UI は 19 言語で提供する。設定メニューから各言語の自言語表記で選択
  できる: English / 日本語 / Español / Português (Brasil) / 简体中文 /
  繁體中文 / Deutsch / Français / 한국어 / Italiano / Русский / ไทย /
  Türkçe / Bahasa Indonesia / Polski / Tiếng Việt / हिन्दी / العربية /
  Українська。
- アラビア語など右横書きの言語ではドキュメントを `dir="rtl"` に切り
  替えてレイアウトを反転する。
- 言語設定はブラウザの localStorage に保存。
- ロール結果はデータとして同期し、表示は閲覧者の言語で整形する。
- チャットの各メッセージは原文の言語を保持する。自動翻訳層はこれを
  「翻訳元」として UI 言語に変換する
  （§3.6 と [`TRANSLATION_API_RESEARCH.ja.md`](TRANSLATION_API_RESEARCH.ja.md)）。

### 3.12 キャラクター
- プレイヤー（人）とは別に「キャラクター」の概念を持つ。
- キャラクターは 名前 / 背景情報（公開）/ メモ（非公開）/ パターン一覧 /
  画像（任意）を持つ。
- キャラクター詳細に見た目の画像を 1 枚添付できる。ファイルを選んだ
  直後にクロップダイアログを表示し、1:1 アスペクト固定・円形プレビュー
  （フィードや参加者一覧の円形アバターと一致）で位置・ズームを調整して
  確定する。確定時・読み込み時にサイズを検査し、長辺 2560px・約 2MB を
  超える場合は自動で縮小・JPEG 圧縮する。JSON インポート経由で取り込ん
  だ画像は作者が決めた構図を尊重し、クロップを経由しない。キャラクター
  情報では小さなサムネイルで表示し、タップで拡大表示する。
- キャラクター画像はルーム内の他プレイヤーへ同期される。フィードで名前を
  タップして開く参加者カードに、その参加者の現在の画像が表示される。画像は
  ロスター（参加者一覧）とは別経路で送られ、変化したときだけ送信する。
- 複数のキャラクターを保持でき、操作するキャラクターを任意で切り替えられる。
- キャラクターとして発言・ロールすると、名前は「{キャラ名}（{PL 名}）」と表記される。
- 背景情報はルーム内に共有される。メモは端末内のみで共有されない。
- パターンはキャラクターごとに保持される。
- 各キャラクターは JSON ファイルとして書き出し・読み込みできる。書き出しに
  非公開のメモを含めるかどうかはキャラクターごとに保存され（既定は含めない）、
  画像は常に含める。
- キャラクター詳細（画像・背景情報・メモ）は、選択中のキャラクターが
  あれば常に表示する（折りたたみ表示にはしない）。
- 参加者一覧では各参加者の行を開いてキャラクターの詳細（名前・背景）を閲覧できる。

### 3.13 アプリ的な UI
- 「ダイスを振る」シートは、ダイス式（個数・種類・補正）を 1 行に並べる。
  個数は 1〜10 のステッパー、種類は `<select>`、補正は −／＋ ステッパー。
  振る前のプレビューは「個数 × 種類 ± 補正」の展開形（例: `3 × D6 + 2`）
  で、用途のアクセント色を添えて表示する。TRPG 初心者が「何 × 何」かを
  振る前に読み取れるようにするのが目的で、フィードの詳細行はベテラン向け
  に従来の `NdM±k` 表記を維持する。
- 使用頻度の低い操作（プレイヤー名・言語・テーマ・文字サイズ・入力中
  シグナル）は設定メニュー内に格納し、「言語と翻訳」「外観」「入力中
  の表示」「このアプリについて」といった見出しでグループ化する。各行に
  Lucide アイコンを並べてパネルを「ひと目で目的が分かるリスト」として
  読めるようにする。十分に高い画面ではドロップダウン、そうでなければ
  全画面高のドロワーで開く。
- 設定からカラーテーマを選べる。6 テーマ（暗色 4・明色 2）を用意し、選択は
  ブラウザに保存する。
- 設定から文字サイズ（小・中・大）を選べる。UI 全体が連動して拡縮し、
  選択はブラウザに保存する。
- キャラクターの背景情報・メモは選択中のキャラクターがあれば常時表示し、
  テキストエリアを複数行に拡張する。
- プレイヤー名・キャラクター名・ルーム名の変更やパターンの保存は Toast で
  通知する。保存ボタンの無い項目（各種名前）は、入力中ではなく入力欄から
  フォーカスが外れた時、またはモーダルが閉じられた時に通知する。
- ルーム参加中はページを離れる前（リロード・戻る・閉じる）に確認ダイアログ
  を表示する。オフライン（ルーム未参加）時は確認しない。
- すべての確認ダイアログ（フィードのクリア、GM のルーム終了、キャラクター
  /パターン/過去セッションの削除、パターンの上書き 等）はブラウザ標準の
  `window.confirm` ではなくアプリのテーマに馴染んだ独自ダイアログを使う。
  破壊的操作ではキャンセルボタンに初期フォーカスを当て、閉じた後は呼び出し
  元のフォーカス位置に戻す。
- 履歴＆チャットを主画面とし、画面の大半を占有する。最小限の状態
  （ルーム・キャラクター・参加者数）はヘッダーに常時表示する。
- ヘッダーのルーム／キャラクター表示はタップでそれぞれのシートを開く。
  キャラクター未選択時の表示は「なし（PL 本人）」とする。
- ルームシートの参加者詳細は開閉キャレットを目立たせ、全員の詳細を
  一括で開閉するボタンを用意する。
- ルーム／キャラクター／ダイス／パターンはボトムドックから必要時に
  シート（オンデマンドのパネル）として開く。モバイルではボトムシート、
  デスクトップでは中央モーダルとして表示する。各シートはタイトル + ×
  をピン留めヘッダに固定し、本文が長くてもタイトルが流れない作りにする。
- アプリ内のアイコンはすべて統一テーマに揃える。UI 部品・意味的概念は
  Lucide、ダイスは Game Icons の d6 シルエットを唯一の表象として再利用する
  （[CREDITS](CREDITS.ja.md) 参照）。
- サイト名・ライセンス・GitHub リンクは設定メニューの下部に格納する。
- プレイヤー名が未設定の場合は入力を必須とし、入力するまで利用を開始できない
  （設定からいつでも変更できる旨も案内する）。
- 初回起動時に使い方をオーバーレイ表示するチュートリアルを出す。設定メニュー
  からはいつでもヘルプとして再表示できる。

### 3.14 過去のルーム履歴
- ルームでのロール・チャット・マーカーは「セッション ID」単位で IndexedDB に
  永続化する。同じコードを使い回しても別日の会話は別セッションに分かれ、
  セッション中にコードを変更しても 1 つのセッションとして連続する。
- ユーザー操作（ダイスロール・チャット発言・ファイル添付）が何も無いまま
  退室したセッションは、退室と同時に永続ログから消す。短時間の入退室で
  「過去のルーム」一覧が空のエントリで埋まらないようにするため。
- 同じコードで再入室した場合、前回のセッションがまだ閉じられていなければ
  （`SessionRecord.closed !== true`）そのセッションを再利用する。離脱と
  再参加・リロード後の再ホストなどは 1 件の履歴にまとまる。GM が明示的に
  ルームを閉じる（クライアント側はその通知を受け取る）と、そのセッションは
  `closed: true` になり、その後同じコードで入室すると新しい履歴が作られる。
- セッションごとに最後に取得できたプレイヤーの画像（ポートレート）も
  永続化する。後から履歴を見たときに当時のキャラクター画像を表示できる。
- ロビーの「過去のルーム」一覧から過去セッションを開いて、その回のフィードを
  読み取り専用で閲覧できる。フィードは ALL / ロール / チャット / ファイルの
  フィルタに対応し、画像はライトボックスで拡大できる。
- 読み取り専用フィードのキャラクター名をタップすると、エントリのスナップショット
  （キャラクター名・背景）と保存された最後のポートレートでプレイヤー詳細を
  表示する。
- セッションは個別に削除でき、まとめて全削除もできる。削除時はそのセッションの
  ログ・メタデータ・ポートレートをすべて消す。確認ダイアログを必須とする。

### 3.15 テーブルマップ

- ルームにマップ機能を備える。GM が背景マップ画像を 1 枚アップロードし、
  その上にスクエアグリッドと、キャラクタートークン・GM 専用トークンを
  配置する。プレイヤーはトークンをドラッグして動かせる（PC トークンは
  オーナーと GM、GM 専用トークンは GM のみ）。
- 背景マップは 1 シーン 1 枚で、長辺 3000px を上限としてホストで自動
  縮小し、PNG / JPEG として保持する。3MB を超える場合は P2P 経路で
  複数チャンクに分割して送信する。背景なし（純グリッドのみ）も使える。
- 背景マップは GM がローカルファイルからアップロードするか、画像 URL を
  指定して取得する。URL から取得した画像も同じダウンスケール・チャンク
  送信パイプラインを通り、参加者へ自動同期される。URL の形式不備・
  CORS / ネットワーク失敗・画像でないレスポンスはそれぞれ別メッセージで
  GM に通知する。
- アプリ内ピッカーから [trpg-map-organizer](https://yamadar.github.io/trpg-map-organizer/)
  の公開マップ（303 点 / 4 カテゴリのタグ）を選んで背景に適用できる。
  ピッカーは初回表示時に maps.json と i18n.json を 1 回ずつ取得し、
  以降はメモリにキャッシュする。タグ表示は UI 言語に追従（ja は原語、
  それ以外は i18n.json の英訳、未翻訳タグは原語フォールバック）。
  選択した画像はオリジナル解像度の WebP を URL 経由で読み込み、
  以降は URL 取得経路と同じパイプラインで配信される（upstream は
  WebP 化で十分なファイルサイズになったため、専用の中解像度 JPEG
  ティアを廃止した）。
- ギャラリーのサムネイル右上にプレビューアイコンがあり、タップで
  オリジナル画像（WebP）を全画面表示する。プレビューでは前後のマップへ
  prev/next ボタン（モバイルはスワイプ）で移動でき、移動時は
  サムネイル選択も同期、現在のフィルタ絞り込み結果を引き継ぐ。
  選択サムネイルがビュー外なら自動でスクロールしてビュー内に収める。
  画像の真下にマップ説明文を表示する。
- 背景マップのソース選択は「アップロード / ギャラリー / URL / プリセット」
  の 4 タブ UI に統合する。タブはアイコンのみで、選択中タブの名前と
  短い説明を直下に表示する。マップが設定済みなら「画像を変更 /
  マップを外す」操作は常にタブの外に可視で配置し、タブを切り替えずに
  差し替えできる。
- グリッドは「なし / スクエア」を選べる。GM がセルサイズ・原点オフセット
  （背景に描かれた grid との位置合わせに必須）・線色・線の透明度を調整
  できる。トークンドラッグ時の「スナップ ON/OFF」を切り替えられる。
- トークンは 2 種類。
  - **PC トークン**: セッションキャラクターと紐付き、画像はキャラクター
    ポートレートを再利用する。当該キャラのオーナーと GM が動かせる。
    配置はオーナー本人または GM の明示操作で行い、同一キャラで複数
    トークンを置くこともできる（双子・分身ギミック用）。削除は GM のみ。
  - **GM 専用トークン**: PC に紐付かない（NPC・モンスター・障害物用）。
    GM のみ追加・移動・削除できる。画像は専用フロー
    （長辺 300px・約 200KB）でアップロードする。
- GM はマップに置く前に **NPC ライブラリ** へキャラを登録できる。
  ライブラリのエントリは「名前 + 画像」だけのテンプレートで、配置時
  に GmToken にコピーされる（ライブラリを編集しても既配置のトークン
  には影響しない）。
- 配置済みトークンをタップすると編集ポップオーバーが開く。GM 専用
  トークンはラベルと画像を変更でき、PC・GM 共通で GM は削除できる。
- トークン位置は px ベースで保持し、表示時にグリッドへスナップする
  （スナップ OFF 時は自由配置）。
- 同期は既存のホスト権威 / last-write-wins モデルを踏襲する。ドラッグ
  中の位置は約 20Hz に間引いて送り、ドラッグ確定時に最終位置を送る。
  受信側のクライアントは楽観的に即時表示するが、ホストの確定で上書き
  される。
- 新規参加者・リロード復帰時は、ホストの welcome スナップショットに
  テーブル状態（背景・グリッド・トークン一覧）を同梱して同期する。
- テーブル状態は IndexedDB に sessionId 単位で永続化し、リロードしても
  復元される。ルームエクスポート ZIP には `table.json` と
  `attachments/maps/*` を追加する（マニフェスト v6 にバンプ）。
- GM はテーブルの現状を名前付きで **テーブルライブラリ** にも保存
  できる。永続化は IndexedDB の `tabletopLibrary` ストア（DB v8）に
  グローバル（セッション横断）で行い、シナリオを事前に用意して
  どのルームでもロードできる。2 種類のフレーバーがある:
  - **テンプレート**: PC トークンを除いた初期配置 + ビューポート中央を
    `pcSpawn` として保存。ロード時は GM の手元 PC を `pcSpawn` 周りに
    再配置するので、シナリオを切り替えても PL が再配置を強いられない。
  - **セーブ**: PC を含む現在状態のスナップショット。ロード時はその
    まま復元される。
  ロードは新 HostMessage `tabletopState` で全クライアントへ配信し、
  マップ画像は既存の `mapMeta` / `mapChunk` 経路でストリームする。
- モバイルでは他のパネルと異なり、テーブルマップは Dock シートではなく
  **全画面モード**として表示する。Dock のテーブルマップアイコンで起動し、
  専用の閉じるボタンで終了する。全画面中も発言・ロールが見えるよう、
  画面下からスワイプアップで開く高さ可変の bottom sheet にフィードを
  表示する（つまみで高さ調整）。デスクトップでも同じ全画面モードを採用する。
- 操作: パン（タッチ 2 本指、マウスは右ドラッグまたは Space + ドラッグ）、
  ズーム（ピンチ / マウスホイール、レンジ 25% – 400%）、トークンドラッグ
  （シングルタップ + ドラッグ）。同一ジェスチャ内でピンチとドラッグを
  混在させない（Konva 公式パターン）。

## 4. 非機能要件

- SPA（シングルページ）。
- 完全な静的サイト。サーバー不要。
- レスポンシブ（PC / モバイル）。
- PWA としてインストール可能。Web マニフェスト・各サイズのアイコン
  （192 / 512 / maskable / Apple touch 1024）・アプリシェルを
  precache する Service Worker を備え、iOS / Android のホーム画面に
  追加するとブラウザ UI のない全画面ウィンドウで起動できる。リアルタイム
  P2P アプリのためオフライン動作は対象外。Service Worker はアプリ
  シェルの precache のみ行う。
- ライセンス: MIT。

### リアルタイム同期方式

ホスト権威型 (host-authoritative)。GM がホストとなり、全プレイヤーは GM に接続する
スター型トポロジ。GM が共有状態（参加者・履歴・チャット）を保持し、イベントを全員に中継する。

WebRTC の NAT 越えには STUN に加えて TURN（中継）サーバーを使う。公衆 Wi-Fi の
対称型 NAT や UDP 遮断下でも接続できるよう、既定では Open Relay Project の無料
公開 TURN を使用する。`VITE_TURN_*` ビルド変数で自前の TURN サーバーに差し替え
られる（`.env.example` を参照）。TURN は通信を中継するだけでアプリのバックエンド
ではないため、静的サイト構成は維持される。

## 6. データモデル

> 実装の型から重要なフィールドだけを抜粋した概念図。フラグ・スナップショット系の
> フィールド（`Pattern.hidden` / `RollResult.isGM` / `ChatMessage.file` 等）は
> 実コードを参照のこと。

```ts
DiceType   = 'D4'|'D6'|'D8'|'D10'|'D12'|'D20'|'D100'
PatternKind = 'damage' | 'judgment'

Lang        = 'en' | 'ja' | 'es' | 'pt-BR' | 'zh-CN' | 'zh-TW' | 'de'
            | 'fr' | 'ko' | 'it' | 'ru' | 'th' | 'tr' | 'id' | 'pl'
            | 'vi' | 'hi' | 'ar' | 'uk'

Pattern    = { id, name, kind, diceType, diceCount, modifier }
// RollResult / ChatMessage は発信者を (playerId, characterId) だけで
// 識別する。名前・キャラ名・背景・GM マークは sessionCharacters の
// per-character レコードから表示時に引く（v1.74 で同梱廃止）。
RollResult = { id, patternName, kind, diceType, diceCount,
               faces: number[], modifier, value, playerId, characterId,
               hidden, timestamp }
ChatMessage = { id, playerId, characterId, text, timestamp, lang, ... }
// Player はアクティブキャラクターの公開情報のみ持つ。メモは同期されない。
Player      = { id, name, isGM, characterId, characterName, background, lang }
Character   = { id, name, background, memo, patterns: Pattern[], lang,
                image?, exportMemo? }

// 永続ログのためのルーム識別子。create / join のたびに sessionId が
// 発番され、リロード・再接続・コード変更を跨いで安定する。前回のセッションが
// まだ閉じられていなければ（`closed !== true`）、同じコードで入り直したときに
// その sessionId が再利用される。
SessionId   = string  // 例: "s-mfp7n7z9-9wk2x4"
SessionRecord = { sessionId, code, name, role: 'host'|'client'|'unknown',
                  firstAt, lastAt, closed? }
// 過去ルーム履歴のためのキャラクター別レコード（IndexedDB v5）。
// 画像と発信者情報（playerName / characterName / background / isGM）を
// (sessionId, playerId, characterId) 単位で保持。characterId は
// `Character.id` か、旧データから移行された `@n:<encoded characterName>`、
// もしくは「PL本人」を表す '' のいずれか。
SessionCharacterRecord = { sessionId, playerId, characterId,
                           playerName, characterName, background,
                           isGM, image, updatedAt }

// 端末ローカルのフィード注釈（同期されない）。ルームイベントを記録する。
MarkerType  = 'created'|'joined'|'youLeft'|'youClosed'
            | 'gmClosed'|'hostLost'|'playerJoined'|'playerLeft'
            | 'reconnecting'|'reconnected'|'reconnectFailed'|'codeChanged'
SystemMarker = { id, timestamp, type: MarkerType, roomCode?, playerName? }
FeedItem    = roll | chat | system marker, merged and sorted by time

// テーブルマップの共有状態。ホスト権威で同期され、welcome スナップショット
// に同梱される。背景は 3MB を超える場合チャンク分割転送する。
TabletopState = {
  map?: { id, name, width, height, dataUrl },
  grid: { kind: 'none'|'square', cellSize, originX, originY,
          strokeColor, strokeOpacity, snap },
  tokens: Token[],
  npcLibrary: NpcDef[],          // GM 用 NPC スタッシュ（配置とは独立）
  pcSpawn?: { x, y }             // テンプレート由来。PC 配置の初期点
}
Token = {
  id, kind: 'pc'|'gm',
  x, y,                  // px 座標。表示時にグリッドへスナップ
  ownerPlayerId?: string // pc: キャラのオーナー。gm: なし
  characterId?: string   // pc のみ
  image?: string         // gm のみ（pc はキャラのポートレートを参照）
  label?: string         // gm: 任意の表示ラベル
}
NpcDef = { id, name, image }     // NPC ライブラリのエントリ（配置の素材）

// GM のテーブルライブラリ。グローバル（セッション横断）に IndexedDB の
// tabletopLibrary ストアへ保存され、シナリオの使い回しに使う。
SavedTabletop = {
  id, name,
  kind: 'template'|'save',       // テンプレートは PC を除いて pcSpawn を持つ
  state: TabletopState,
  createdAt, updatedAt
}
```

参加者の色は `playerId` のハッシュから決まり、同期不要で全クライアントが一致する。

`lang` フィールドは原文の言語を保持し、チャットの自動翻訳で原言語として
使われる（[`TRANSLATION_API_RESEARCH.ja.md`](TRANSLATION_API_RESEARCH.ja.md)）。

7. **Tests & review** — テスト整備・セルフレビュー・修正
8. **Docs & deploy** — README・LICENSE・GitHub Actions・GitHub Pages 公開
